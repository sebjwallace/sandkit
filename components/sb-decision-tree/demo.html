A decision tree that shows the way a case went, and which answers would have changed where it ended up.

About

A decision tree asks one question at a time, and each answer leads to the next question or to an outcome. Rules for lending, triage, eligibility and diagnosis are often trees, and so are many machine-learning classifiers. Seen whole, a tree shows every way a case can go. With one case traced through it, it shows why that case ended where it did: the value it had at each question, and the answers that would have taken it somewhere else.

Where it helps

  • Explaining one decision. Trace a case and read its way down, with its value at each question.
  • Seeing what would change it. The branches not taken that lead to a different outcome are marked with where they lead, so the questions that decided the case stand out from those that didn't matter.
  • Seeing where cases go. Give counts, and each branch is as thick as the share of cases that took it.

Where something else fits better

  • A process that loops or comes back together. A tree only branches. When steps lead back or join, use a flowchart.
  • Rules applied in order, rather than a branching set of questions. A list of rules with the one that fired marked reads better.
  • Choices under uncertainty, with probabilities and payoffs. This tree's branches are answers, not chances; it doesn't work out expected values.

Getting started

<script src="components/sb-decision-tree/sb-decision-tree.js"></script>
<sb-decision-tree></sb-decision-tree>

<script>
  const tree = document.querySelector('sb-decision-tree');
  tree.root = { id: 'rain', question: 'Raining?', children: [
    { id: 'coat', answer: 'yes', outcome: 'Take a coat' },
    { id: 'cold', answer: 'no', question: 'Below 10°?', children: [
      { id: 'jumper', answer: 'yes', outcome: 'Wear a jumper' },
      { id: 'tshirt', answer: 'no', outcome: 'T-shirt' }
    ] }
  ] };
  tree.trace = [{ id: 'rain', value: 'no' }, { id: 'cold', value: '14°' }, { id: 'tshirt' }];
</script>

A node with children is a question; one without is an outcome. Each child's answer labels the branch into it. You never place anything: the tree lays itself out, down the page or, with direction="right", across it.

Making it reveal, not just display

  • Let the model decide, and trace it. The model applies its own rules and sets trace to the way the case went. The component never evaluates anything, so the tree can't disagree with the model.
  • Give the value, not just the answer. "42k" on the income question says more than the branch "30–60k" alone.
  • Set counts when the tree sorts many cases, so the busy branches and the rare outcomes stand out.
  • Connect it. Point the prose at a question with highlight, and listen for sb-select to explain the rule behind a node.

Examples

A loan application

The lender's rules as a tree. Income is asked first, and decides which debt question comes next: higher earners are allowed more debt. Only the middle band is asked how long they've been in work. Move the applicant's figures, or try a 45k earner a year into a job: referred, though the dashed branch shows two years would have meant approval. With more debt, the years never come into it.

Naming a tree from its leaf

A key for trees in a park, with how many of the 120 surveyed came out at each. The first question does the most work: broad leaves are three in four. Oak is the most common tree, and larch and horse chestnut the rarest. Pick a leaf someone brought back, such as a small, saw-edged one, and follow it through the key.
