Code or pseudocode, walked through a step at a time, with the variables beside it.

About

Reading code tells you what it says; watching it run tells you what it does. This shows a piece of code, or pseudocode, beside its variables, and walks through it a step at a time: the line running now is marked, and the variables that just changed stand out. The steps come from the sandbox's own model, which records them as it runs, so what you see is exactly what the model did.

Where it helps

  • Understanding an algorithm. Sorting, searching, making change, a recipe followed to the letter.
  • Showing why a result came out as it did. Step back to the moment a variable went wrong.
  • Explaining code in prose. Point at a line or a variable from the text and it lights up.

Where something else fits better

  • The rules a model follows, rather than a procedure: a rules table marks the rule that applies.
  • Branches you want to see at a glance: a flowchart shows every way through, not one run.
  • Long programs. Show the few lines the question is about.

Getting started

<script src="components/sb-code/sb-code.js"></script>
<sb-code controls></sb-code>

<script>
  const code = document.querySelector('sb-code');
  code.code = 'total = 0\nfor each n in numbers\n  total = total + n';

  // The model records each step as it runs: the line, and the variables after it.
  const trace = [];
  let total = 0;
  trace.push({ line: 1, variables: { total } });
  for (const n of [4, 7]) {
    trace.push({ line: 2, variables: { total, n } });
    total += n;
    trace.push({ line: 3, variables: { total, n }, note: `Added ${n}` });
  }
  code.trace = trace;
</script>

Keywords common to pseudocode, JavaScript and Python are coloured for you. For your own language, add its words: code.syntax = { ...code.syntax, keywords: [...code.syntax.keywords, 'reorder'] }.

The controls attribute adds buttons and a slider to step through; without it, the sandbox moves things along by setting step. Either way, sb-step tells the sandbox when a viewer moves.

Making it reveal, not just display

  • Let the model record the trace, rather than writing steps by hand, so they can never disagree with what the model does.
  • Record the variables that matter, not every one. Copy lists and objects as you record them, so each step keeps its own values.
  • Add a note where a step needs a reason, such as "3 is bigger than 1, so swap them".
  • Connect it. On sb-step, update the rest of the sandbox, such as a picture of the list being sorted.

The full contract, including every property, event and styling hook, is in the manifest.

Examples

Giving change, in pseudocode

The fewest coins for an amount: take the biggest coin that fits, as often as it fits, then the next. Change the amount and the model runs again.

Sorting a list, in JavaScript

Bubble sort walks through the list, swapping neighbours that are the wrong way round. Point at the comparison, the swap, or the list; or point at a variable, beside the code or in it.
