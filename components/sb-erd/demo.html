An entity relationship diagram whose lines run from the exact field to the exact field.

About

Wherever information is kept, it is kept as things that refer to each other: a loan refers to a book and a member, an order to a customer. An entity relationship diagram draws those things as boxes listing their fields, and each reference as a line. Here, every line starts at the very field that holds the reference and ends at the very field it refers to, so you never have to guess which field a line belongs to.

Where it helps

  • Seeing how information hangs together. What a library, a shop, a clinic or a school needs to keep, and how each piece points at the others.
  • Following a reference. Point at a field and its line lights up, along with the field at the other end. Point at a key and every field that refers to it lights up.
  • Explaining a design. Point at fields from the prose, so a sentence about "who borrowed what" lights the fields that record it.

Where something else fits better

  • States and transitions, or flows. Use a graph of nodes and edges.
  • The records themselves. A diagram shows the shape of the information; a table shows what's in it.
  • Very large schemas. Fifty boxes are hard to read anywhere. Draw the part the question is about.

Getting started

<script src="components/sb-erd/sb-erd.js"></script>
<sb-erd></sb-erd>

<script>
  document.querySelector('sb-erd').entities = [
    { id: 'customers', name: 'Customer', x: 0, y: 0, fields: [
      { name: 'id', type: 'int', key: 'primary' },
      { name: 'name', type: 'text' }
    ] },
    { id: 'orders', name: 'Order', x: 260, y: 0, fields: [
      { name: 'id', type: 'int', key: 'primary' },
      { name: 'customer_id', type: 'int', references: 'customers.id' }
    ] }
  ];
</script>

Give each entity a position, its top-left corner in pixels, and leave room between boxes for the lines. A field with references draws a line to the field it names; name only the entity ('customers') and the line ends at its title.

Making it reveal, not just display

  • Place related entities side by side, so lines run across rather than around. The line leaves from whichever side faces its target.
  • Show the fields that matter for the question, not every column a real database has.
  • Point at relationships from the prose. Set highlight when a sentence talks about a field; the line and the other end light up with it.
  • Connect it. Listen for sb-select to show an entity's records, or explain a field, elsewhere in the sandbox.
