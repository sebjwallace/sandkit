What's really in a pile of data: every field, what it holds, and what's surprising about it.

About

Data rarely matches its description. A field everyone says is always there turns out to be missing one time in twenty; a number arrives as text twice in a thousand; a status has a value nobody meant to allow. A profile reads every sample and tells you the shape the data really has: each field, its types, how often it's there and the values it takes, with the surprises marked on the fields they concern.

Where it helps

  • Meeting new data. Before modelling orders, sightings or events, see which fields matter, which never change and which are unreliable.
  • Checking an assumption. "Every order has a customer" is one glance: present 100%, or not.
  • Seeing what a subset is like. Click a value to narrow the samples, and every field that changed is marked with what it was before.

Where something else fits better

  • Reading the samples themselves. A table shows rows; a profile shows what the rows have in common.
  • One document. A single JSON value is easier to read as it is, with the parts that matter pointed out.
  • How values change over time. That's a chart: a profile sees the samples all at once.

Getting started

<script src="components/sb-profile/sb-profile.js"></script>
<sb-profile></sb-profile>

<script>
  const profile = document.querySelector('sb-profile');
  profile.options = { id: 'orderId' };   // so findings name samples by their id
  profile.samples = orders;               // raw samples: the profile works everything out
  profile.addEventListener('sb-select', (e) => {
    profile.samples = orders.filter((order) => order[e.detail.path] === e.detail.value);
  });
</script>

Hand it the samples as they are. Click a field's name to see its values, or its numbers as a histogram; clicking a value tells the sandbox, which can narrow the samples and set them again.

An agent can run it too

The same analysis runs from the command line, with no page, so an agent can profile source material before a sandbox exists, and read a short summary instead of thousands of samples:

node tools/analyse.mjs profile data/ --md --id orderId

What the agent reads and what you see here come from the same function, so they always agree.

Making it reveal, not just display

  • Give it every sample, not a tidy few. Gaps and odd values hide in the long tail.
  • Name the id field, so "1 is a string" says which order, and someone can go and look.
  • Let clicks narrow the samples. The changes marked after narrowing are often the finding: cancelled orders never have a refund, or one surveyor records every odd count.

Wildlife sightings

Eighty records from volunteers counting animals at four sites.
