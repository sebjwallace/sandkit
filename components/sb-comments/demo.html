Comments from the people exploring a sandbox, each citing what it's about.

About

A sandbox carries understanding from a model to the people exploring it. Comments carry it back. Press Comment, click whatever you have something to say about, and write it down; the comment remembers exactly what it was about, so no one has to describe "the third row of the second table". When you're done, copy your comments as a prompt for the agent building the sandbox, or download them as a file to send to whoever asked for your thoughts, and the page is left as it was.

Where it helps

  • Feedback while exploring. Note a doubt the moment it occurs, pinned to the part it's about.
  • Gathering views. Send a sandbox to the people who know the subject; they comment and send the file back.
  • Telling an agent precisely what to change. Each comment cites the codes it's about, the view, the version and the state of the model.

Where something else fits better

  • A conversation. For back-and-forth, talk; comments are for considered notes, sent in one go.
  • Changing the model. Parameters and controls change it directly. Comments are about what should change.
  • Notes for every reader. Notes everyone should see belong in the sandbox itself, as a callout or annotations.

Getting started

<script src="components/sb-comments/sb-comments.js"></script>

<sb-shell heading="My sandbox">
  <sb-comments id="feedback" slot="actions"></sb-comments>
</sb-shell>

<script>
  comments.context = { title: 'My sandbox', version: '0.3.0', goal: 'What it helps people understand.' };
  comments.snapshot = () => ({ chapter: tabs.selected, step: model.state.time });
  comments.addEventListener('sb-pick', (e) => comments.pick(refsAt(e.detail.x, e.detail.y)));
</script>

The component never searches the page. In comment mode it says where the viewer clicked, and the sandbox answers with what's there, using refsAt from the locating practice. What the agent does with the comments it receives is in the feedback practice.

Making it reveal, not just collect

  • Give the parts people talk about a code. A comment on a part with a code cites it exactly; one without cites only its view.
  • Snapshot what matters. The chapter, the step, the scenario: whatever a comment can't be understood without.
  • Say what changed because of them. When a version answers comments, the journal says which, so people see their comments made a difference.

The full contract, including every property, event and styling hook, is in the manifest.

Examples

Comments on a recipe

Press Comment, click an ingredient or a step, and write what you think. Shift-click to add another part to the same comment. Press Done to copy or download them, or Cancel to forget them. What you'd send shows on the right.

Ingredients

  • 200 g plain flour
  • 2 eggs
  • 300 ml milk

Method

  1. Whisk the flour, eggs and milk until smooth.
  2. Rest the batter for 30 minutes.
  3. Fry thin pancakes in a hot pan.
