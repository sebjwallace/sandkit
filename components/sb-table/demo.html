Rows and columns to sort, search and filter, with what just changed marked.

About

Many models are a set of comparable things: stores and their stock, teams in a league, patients on a ward, the planets. A table lays them side by side, so people can put them in order, narrow them down to the ones that matter, and compare. When the model moves on, the table marks which values changed, so you can see what a step actually did.

Where it helps

  • Comparing many things on several measures. Which store is lowest on stock? Which team has scored most? Click a heading and see.
  • Finding the few that matter. Search, or filter from the model ("only the overspent ones"), and the table says how many it's hiding.
  • Seeing what a step changed. After each step of the model, the cells that changed are marked, with which way numbers moved and what they were before.
  • Grounding the prose. Point at a row, column or cell from the explanation, and it lights up.

Where something else fits better

  • Things that happened in order. A stream of occurrences is a log, not a table.
  • Values over time. A table shows where things stand; a chart shows how they got there.
  • The rules a model follows. A rules table can mark the rule about to apply and the one just applied.
  • A handful of numbers. Three values read better in a sentence.

Getting started

<script src="components/sb-table/sb-table.js"></script>
<sb-table search></sb-table>

<script>
  const table = document.querySelector('sb-table');
  table.columns = [{ key: 'name', label: 'Store' }, { key: 'stock', label: 'Stock' }];
  table.rows = [
    { id: 'north', name: 'North', stock: 37 },
    { id: 'south', name: 'South', stock: 0, tone: 'bad' }
  ];
</script>

Rows are plain objects. Give each an id so the table can match it from one update to the next, and a tone (good, warn or bad) where it deserves attention. Columns can format their values; numbers line up on the right by themselves.

Making it reveal, not just list

  • Set the rows again after every step. That's all it takes for the changes to be marked. Hover a marked cell to see what it was.
  • Show the columns that answer the question, not every field the model has. Fewer columns, compared more easily.
  • Use tone for the rows that matter now, such as a store that has run out, and only those.
  • Filter from the model, with filter, when the question is about a subset. The count keeps the rest in mind.
  • Connect it. Listen for sb-select to follow a row elsewhere in the sandbox, and set highlight when the prose points at something.

Examples

The planets

Click a heading to put the planets in order: by distance, size, the length of a day or a year. Change your weight to see what it would feel like on each, and which way it moved.

A household budget

A month's spending against the budget. Search it, or show only what's over. Point at food or what's left to see it light up.
