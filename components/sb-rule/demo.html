One rule as a card: which way it goes right now, and whether it holds.

About

A rule says what must, must not or may happen, sometimes only in certain situations. Written in a list or a document, it's easy to agree with and hard to picture. This card lays one rule out to read at a glance, with its MUSTs and values standing out, and then lets the model show it at work: which branch is in force right now, and whether what's happening keeps to it.

Where it helps

  • Seeing a rule respond. Beside the knobs of a model, a few rule cards show limits tightening, branches switching and rules breaking as people push the situation.
  • Reading rules one at a time. Each card holds one situation, so a rule can be discussed, pointed at and cited by its code.
  • Any way of stating rules. Mandates and conditionals cover most, but a subject's own keywords and modal words (SHALL, SHOULD) work just as well.

Where something else fits better

  • Many rules at once, with the one about to apply marked: a rules table.
  • A sequence of things happening, start to finish: a scenario.
  • Rules that branch many levels deep to an outcome: a decision tree.

Getting started

Give each card a rule. Lines have an optional keyword, text and a depth; the model says which lines apply now (path) and whether the rule holds (status). See the manifest for the recommended shapes and the full contract.

card.rule = {
  kind: 'CONDITIONAL', code: 'ROV-R2', title: 'Wheel slip',
  lines: [
    { keyword: 'GIVEN', text: 'the rover is on a drive' },
    { keyword: 'IF', text: 'wheel slip is above 60%' },
    { text: 'the drive MUST stop', depth: 1 },
    { keyword: 'ELSE' },
    { text: 'the rover MAY drive blind', depth: 1 }
  ]
};
card.path = [0, 1, 2];        // the lines that apply now
card.status = 'broken';       // or 'holds', 'idle'

Clicking a line fires sb-select and changes nothing by itself. Below, clicking a condition makes it true.

Making it reveal, not just state

  • Drive it from the model. Recompute path and status on every change, so a rule visibly switches branch and breaks. A rule that never changes is only text.
  • Put the knobs near the rules. The situation and the rule should be in view together, so people can push one and watch the other.
  • Write rules with values. "Steeper than 30°" can be checked; "too steep" can't.
  • Point from the prose. One phrase can light the same kind of line across several cards, such as every limit.

Examples

A Mars rover's flight rules

Rovers drive by rules written in advance, because a question to Earth takes twenty minutes to answer.

Slip decides what the rule demands, from stopping outright to driving freely, while the battery rule holds whatever the ground.

Skiing in avalanche country

Backcountry parties settle their limits before they leave, so a good day doesn't talk them into a bad slope.

As the danger rises, the steepest slope allowed falls, and at level 4 or higher most of the mountain is off limits. The kit rule never bends.
