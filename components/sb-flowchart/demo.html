A flowchart, optionally in swim lanes, that shows where a process is and how it got there.

About

A process is a series of steps and decisions: do this, then that; if so, go here, otherwise there. A flowchart lays them out so the whole process can be seen at once. Swim lanes add who does each step, so the hand-overs between people, teams or systems stand out. As the sandbox runs the process, the chart marks the step it's on and the way it came.

Where it helps

  • Following a process through. Step through it and watch the current step move, the path behind it lit up.
  • Seeing who does what. With lanes, every line that crosses from one lane to another is a hand-over, which is often where things wait or go wrong.
  • Seeing where a process branches and loops. Decisions and the loops back to earlier steps are easy to miss in prose.

Where something else fits better

  • States a thing moves between. When it's about what state something is in rather than the steps someone takes, draw a state machine as a graph.
  • Exact positions. The flowchart lays itself out. If the arrangement itself carries meaning, such as a map, place nodes by hand in a graph.
  • Long, strictly linear procedures. A numbered list reads better than a column of boxes.

Getting started

<script src="components/sb-flowchart/sb-flowchart.js"></script>
<sb-flowchart direction="down"></sb-flowchart>

<script>
  document.querySelector('sb-flowchart').data = {
    nodes: [
      { id: 'start', label: 'Thirsty', kind: 'start' },
      { id: 'tea', label: 'Tea or coffee?', kind: 'decision' },
      { id: 'kettle', label: 'Boil the kettle' },
      { id: 'machine', label: 'Use the machine' }
    ],
    edges: [
      { from: 'start', to: 'tea' },
      { from: 'tea', to: 'kettle', label: 'tea' },
      { from: 'tea', to: 'machine', label: 'coffee' }
    ]
  };
</script>

You never place anything: each step goes one rank after the steps that lead to it. Add lanes and give each node a lane for swim lanes. direction="right" runs the chart left to right, with lanes as rows. Kinds are start, end, step (the default), decision and data.

Making it reveal, not just display

  • Run the process through it. As the model moves, set active to where it is and visited to the way it came.
  • Label every branch of a decision, so the question and its answers read together.
  • Use lanes when hand-overs matter, and colour a step with a tone where work piles up or fails.
  • Connect it. Listen for sb-select to explain a step, or to jump the model to it.

Examples

Making a cup of tea

A plain flowchart. Step through making a cup: the current step is marked, and the way you came stays lit. It loops while the tea isn't strong enough.

Eating at a restaurant

Swim lanes for the customer, the waiter and the kitchen. Every line crossing between lanes is a hand-over. Choose which way it runs.
