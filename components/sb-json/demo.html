JSON shown cleanly, with the parts that matter in the spotlight and everything else folded away.

About

Reading about data usually means jumping between a paragraph and a long block of JSON, hunting for the three lines the paragraph is talking about. This component keeps the whole document but puts those lines in the spotlight: everything else folds away into quiet gaps, and the lines that open and close around them stay, so you still see where they live. Unfold a gap, or show everything, whenever you want the full picture. Click any line to see its path, and the note the sandbox wrote for it.

Where it helps

  • Explaining a payload. An API response, a message on a queue, an event, a saved file: prose points at the fields it discusses, and the JSON narrows to them.
  • Documenting data in place. Notes on paths turn the JSON into its own reference: click a field to read what it means.
  • Showing what the model produces. When the model builds a record or a message, show it as it really is, spotlighting the part the current step changed.

Where something else fits better

  • Many records of the same shape. A table lines them up for comparing and sorting.
  • A hierarchy to browse, such as files or an organisation. A tree shows the nesting without the punctuation.
  • The structure of the data rather than an example. An entity diagram shows how kinds of record refer to each other.

Getting started

<script src="components/sb-json/sb-json.js"></script>
<sb-json></sb-json>

<script>
  const json = document.querySelector('sb-json');
  json.value = response;                         // any JSON value
  json.spotlight = ['order.total'];              // fold the rest away
  json.notes = { 'order.total': 'In pence.' };   // shown when it's clicked
</script>

Paths are written as code would reach the part: order.items[0].price. You don't need to work them out: click a line and its path is in the bar above the code, ready to copy. Viewers unfold a gap by clicking it, and show everything with the toggle; the spotlit lines stay marked either way.

Making it reveal, not just display

  • Spotlight what the sentence is about. Make words in the prose set spotlight when clicked, and highlight when pointed at, so reading and looking happen in one place.
  • Write notes for the surprising fields, the ones in pence, the ones that can be null, the ones named misleadingly, rather than for every field.
  • Spotlight what changed. When the model sends a new message, spotlight the fields this step set.
  • Connect it. Listen for sb-select to explain the chosen field elsewhere in the sandbox.

The full contract, including every property, event and styling hook, is in the manifest.
